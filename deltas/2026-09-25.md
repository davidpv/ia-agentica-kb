# Delta 2026-09-25

Ventana: desde el viernes 18 sep 2026. Solo cambios con efecto duradero en procesos de desarrollo con IA agentica.

## 1. Claude Code adopta AGENTS.md como fallback (instrucciones compartidas)

**Qué cambió.** Claude Code 2.1.277 (18 sep 2026) lee `AGENTS.md` cuando no hay `CLAUDE.md` en el proyecto. El comportamiento se configura en «Project instructions» dentro de `/config`. Por defecto es fallback (no merge): si existe `CLAUDE.md`, sigue ganando y se ignora `AGENTS.md` salvo import explícito o modo «ambos».

**Por qué importa.** `AGENTS.md` ya era el formato compartido (Agentic AI Foundation / Linux Foundation; Codex, Cursor, Copilot, Gemini CLI y otros). Hasta ahora, mezclar Claude Code obligaba a duplicar o symlinks. Converge la instruction file como artefacto de gobernanza versionado en Git.

**Caveats enterprise (no triviales).**
- Aún no en Bedrock, Vertex ni Foundry.
- `CLAUDE.local.md` cuenta como `CLAUDE.md` y puede ocultar el `AGENTS.md` del equipo.
- No lee `AGENTS.local.md`, overrides ni skills bajo `.agents/`.
- Sesiones sin feature flags (p. ej. telemetría desactivada) o el primer arranque tras instalar/actualizar pueden no cargarlo; workaround fiable: importar desde `CLAUDE.md`.
- En CI efímero hay que verificar carga antes de borrar symlinks.

**Implicación de proceso.** Dueño de plataforma sobre un único `AGENTS.md` (fuente de verdad); `CLAUDE.md` solo para matices Anthropic o import. Revisar instruction files como configuración de pipeline (PR review), no como notas locales.

## 2. AGENTS.md empieza a usarse como manifiesto de coordinación multiagente

**Qué cambió.** Práctica emergente (señal Codex / equipos con ≥4 agentes en paralelo): extender `AGENTS.md` más allá de instrucciones por sesión con cuatro bloques de coordinación — dependencias entre tareas, milestones binarios, exclusion zones (locks por fichero/recurso) y condiciones de rollback. Sin framework nuevo: Markdown + convenciones que todo agente lee al arrancar.

**Por qué importa.** Los fallos típicos (dos agentes en la misma migración, merges que invalidan supuestos de otros) son de coordinación, no de modelo. El umbral operativo citado es ~4 agentes en paralelo (canales pairwise fuera del seguimiento humano).

**Implicación de proceso.** Antes de escalar multiagente: sección `## Coordination` arriba del fichero; worktrees/PR aislados siguen siendo el harness base; swarms sin exclusiones y rollback = deuda operativa.

## 3. Harnesses generados multi-herramienta (señal secundaria)

Aparecen generadores/adaptadores que producen `AGENTS.md` + reglas por herramienta (Claude Code, Cursor, Codex, etc.) con `verify` / `manifest` / diagnose para drift en CI. Refuerza el mapa base: el harness (instructions + skills + gates) es el producto de ingeniería, no el prompt puntual.

## Acciones recomendadas

1. Inventariar `CLAUDE.md` / `AGENTS.md` / symlinks en repos activos; consolidar en un `AGENTS.md` versionado con dueño de plataforma.
2. Probar carga real en el canal que usáis (CLI local vs Bedrock/Vertex/Foundry vs CI efímero) antes de eliminar workarounds.
3. Si ya corréis ≥3–4 agentes en paralelo en el mismo repo: añadir dependencias, exclusion zones y rollback en `AGENTS.md` (o forzar un agente / worktree por cambio compartido).
4. Tratar cambios de instructions como cambio de configuración: review en PR + política managed-only donde haga falta gobernanza central.
